Actualitzar, protegir i copiar

El manteniment d'un gestor: posar-lo al dia, tancar-ne les portes, copiar-lo i demostrar que la còpia serveix.

Què has de saber abans de començar

Teoria T1.5. La guia G1.3, apartats de WP-CLI, seguretat i manteniment i restauració, és el manual que consultaràs.

Deixaràs el lloc de proves desactualitzat a propòsit, l'actualitzaràs de manera ordenada, activaràs els mecanismes de seguretat del gestor, en faràs una còpia completa i la restauraràs després d'una «avaria». Abans i després de cada pas passaràs una llista de proves.

Amb què treballaràs

L'escriptori de proves de l'A1.2, amb WordPress a proves.internal i tot el que hi has fet a les activitats anteriors. Un client et demana que te'n facis càrrec: fa mesos que ningú no l'actualitza i no hi ha cap còpia.

Què has de fer

  1. Escriu una llista de proves d'almenys vuit files per al teu lloc i passa-la.
  2. Instal·la amb WP-CLI una versió antiga d'una extensió del directori oficial, perquè el tauler en demani l'actualització.
  3. Fes una còpia completa: bolcat de la base de dades i fitxers, i treu-la de l'escriptori.
  4. Fes l'inventari del que cal actualitzar i aplica les actualitzacions d'una en una, en l'ordre que decideixis després de llegir què canvia a cadascuna. Registra cada element amb la versió d'abans i la de després, i torna a passar la llista de proves.
  5. Activa els mecanismes de seguretat del gestor: actualitzacions automàtiques, cap tema ni extensió sobrant, comentaris moderats, registre tancat, editor de fitxers desactivat, wp-config.php protegit i contrasenyes d'aplicació revisades. Resol els avisos crítics de Salut del lloc.
  6. Fes una segona còpia. Simula una avaria: esborra una pàgina, una entrada i una extensió.
  7. Restaura la segona còpia i passa la llista de proves per tercera vegada.

Exemple per al punt 2 (tria l'extensió i la versió a la pestanya «Advanced View» del directori):

cd /var/www/proves.internal
sudo -u www-data wp plugin install hello-dolly \
  --version=1.6 --activate

Primer la còpia

Mai actualitzis sense una còpia recent i provada. Si una actualització trenca el lloc, la còpia és l'única manera de tornar enrere en minuts. Una còpia que es queda al mateix escriptori es perd amb l'escriptori.

Què hi ha dins del bolcat

Obre el fitxer .sql amb less. Són ordres SQL: CREATE TABLE per a cada taula i INSERT amb les files. Busca-hi el títol d'una de les teves entrades: restaurar és tornar a executar aquestes ordres.

Com sabràs que ho has fet bé

  • sudo -u www-data wp plugin list --update=available i wp core check-update no mostren res pendent.
  • sudo -u www-data wp core verify-checksums passa sense errors.
  • sudo -u www-data wp theme list només mostra el tema actiu i, com a molt, un de reserva.
  • Al tauler no surt Aparença → Editor de fitxers de temes.
  • ls -l wp-config.php mostra permisos 640.
  • Després de restaurar, la pàgina, l'entrada i l'extensió esborrades hi tornen a ser, i la llista de proves passa sencera.

Si alguna cosa no va

WP-CLI diu «Error: This does not seem to be a WordPress installation»

Causa No ets a la carpeta del lloc.

Solució Fes cd a la carpeta o afegeix --path=/var/www/proves.internal.

Després de restaurar, les imatges no surten

Causa La còpia de fitxers no incloïa wp-content/uploads o els permisos no són de www-data.

Solució Revisa el contingut del .tar.gz i torna a fer el chown.

«Error establint la connexió amb la base de dades» després de restaurar

Causa El bolcat no s'ha carregat a la base de dades correcta.

Solució Comprova el nom de la base a wp-config.php i torna a carregar el bolcat.

Què has d'entregar

Un repositori a GitHub amb un README.md que tingui la llista de proves amb les tres passades, la taula d'actualitzacions, cada mecanisme de seguretat amb una captura, les ordres de còpia i restauració i la sortida de les comprovacions.

Respon-hi també: en quin ordre has aplicat les actualitzacions i per què, i què hauries fet si una d'elles hagués trencat el lloc?
