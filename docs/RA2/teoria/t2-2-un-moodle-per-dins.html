Un Moodle per dins

Codi, dades i base de dades: on queda cada cosa quan s'instal·la.

Què sabràs fer en acabar

  • Enumerar les tres parts d'una instal·lació de Moodle.
  • Explicar la jerarquia de directoris i per què el web només serveix public.
  • Dir què guarda el directori de dades i per què va fora del web.
  • Explicar per a què serveix el cron.
  • Descriure com s'organitzen categories, cursos, seccions i activitats.

Tres parts

PartContéOn
CodiEls fitxers PHP de Moodle, els temes i els connectorsLa carpeta del lloc, per exemple /var/www/moodle.internal
Dades (moodledata)Fitxers pujats, memòria cau, sessions, còpies de cursosFora del web: /var/moodledata
Base de dadesUsuaris, cursos, notes, registres, configuracióMySQL

Una còpia del lloc sencer necessita les tres. El fitxer config.php, a l'arrel del codi, les lliga: diu l'adreça del lloc, on és moodledata i com connectar amb la base de dades.

La jerarquia de directoris

Des de Moodle 5.1, el codi té una carpeta public i és l'única que ha de servir el servidor web. La resta —la configuració i les eines de línia d'ordres— queda fora de l'abast del navegador.

DirectoriQuè hi ha
config.phpConfiguració del lloc; no és accessible des del web
admin/cli/Eines de terminal: cron.php, instal·lació, actualització
public/L'arrel web: index.php, pàgines i recursos
public/theme/Temes
public/mod/Activitats: assign, quiz, forum…
public/blocks/, public/local/Blocs i connectors locals
moodledata/filedir/Tots els fitxers pujats, amb noms de resum
moodledata/cache/, temp/, sessions/Dades temporals que es poden regenerar

Per què les dades van fora del web

A moodledata hi ha les entregues de l'alumnat, les còpies de cursos i les sessions obertes. Si fos dins de la carpeta que serveix Apache, qualsevol que endevinés la ruta les podria descarregar. Moodle ho comprova en instal·lar-se i no accepta un directori de dades accessible des del web.

El cron

Moltes feines de Moodle no passen quan algú clica: enviar els correus dels fòrums, tancar tasques fora de termini, esborrar temporals, calcular estadístiques. Les fa el cron, un programa que el sistema executa cada minut. Sense cron, Moodle sembla funcionar però els avisos no surten.

On acaba una entrega

Un estudiant entrega practica.pdf en una tasca. La base de dades guarda qui l'ha entregat, quan i la nota. El fitxer va a moodledata/filedir amb un nom de resum com 3f/a2/3fa2…, i no amb el nom original: així, dos fitxers idèntics només ocupen espai una vegada.

Canviar l'aspecte sense tocar el codi

L'aspecte depèn del tema. El tema per defecte, Boost, permet canviar el logotip, el color de marca i afegir SCSS en brut des de l'administració. Instal·lar un tema nou és copiar-lo a public/theme o pujar-lo des del web; Moodle el detecta i en fa l'actualització.

L'informe d'entorn

A Administració del lloc → Servidor → Entorn, Moodle llista els seus requeriments al costat del que té el servidor: versió de PHP, extensions, base de dades, max_input_vars. És el mateix informe que surt durant la instal·lació.

Criteris professionals

  • moodledata sempre fora de l'arrel web.
  • L'arrel web del host virtual apunta a public.
  • Cron cada minut des del primer dia.
  • Temes i connectors només del directori oficial de Moodle.

Errors habituals

El lloc mostra una llista de fitxers o errors després d'instal·lar

Causa L'arrel web apunta a la carpeta del codi, no a public.

Solució Canvia el DocumentRoot al directori public.

Els correus dels fòrums no arriben mai

Causa El cron no s'executa.

Solució Programa'l cada minut i comprova-ho a l'informe de tasques programades.

Resum

  • Tres parts: codi, moodledata i base de dades; config.php les lliga.
  • El web només serveix public.
  • moodledata va fora del web perquè guarda entregues i sessions.
  • El cron fa les feines de fons cada minut.
  • Categoria → curs → secció → recurs o activitat.
