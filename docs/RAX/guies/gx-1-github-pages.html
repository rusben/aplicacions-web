Guia: repositori i GitHub Pages

Crear un repositori, clonar-lo per SSH i publicar-hi un web estàtic.

Què hi ha en aquesta guia

Documentació oficial: Repositoris a GitHub · Connectar-se per SSH · GitHub Pages

  • Punt de partida: un compte de GitHub i una clau SSH pròpia (una VM d'IsardVDI o l'equip personal).
  • Resultat: un repositori públic amb el web pujat i publicat a una adreça https://usuari.github.io/repositori/.
  • Necessària per a totes les activitats i la pràctica d'aquest RA: AX.1 a PX.2.

Crear el repositori i connectar-hi una clau SSH

  1. Genera una clau SSH si encara no en tens cap a la màquina on treballes:

    ssh-keygen -t ed25519 -C "el-teu-correu@exemple.cat"
# Prem Retorn tres vegades per deixar el camí i la frase de pas per defecte

  2. Copia la clau pública i enganxa-la a GitHub, a Settings → SSH and GPG keys → New SSH key:

    cat ~/.ssh/id_ed25519.pub

  3. Comprova la connexió:

    ssh -T git@github.com
Hi username! You've successfully authenticated...

  4. Crea el repositori des de github.com, amb New repository: nom curt, públic, sense plantilla de .gitignore ni llicència de moment.

  5. Clona'l per SSH a la carpeta on treballaràs:

    git clone git@github.com:usuari/repositori.git
cd repositori

Pujar el web i publicar-lo amb GitHub Pages

  1. Afegeix els fitxers del web (com a mínim index.html) dins de la carpeta clonada, amb les subcarpetes de CSS i imatges que calguin.

  2. Puja'ls al repositori:

    git add .
git commit -m "Primera versió del web"
git push

  3. Activa GitHub Pages: a la pàgina del repositori, Settings → Pages → Branch: main i desa. GitHub triga un o dos minuts a publicar-la.

  4. Obre l'adreça publicada, que apareix a la mateixa pantalla un cop llesta: https://usuari.github.io/repositori/.

Com saps que ha quedat bé

  • L'adreça https://usuari.github.io/repositori/ mostra el mateix web que en local.
  • Els enllaços entre pàgines i les imatges funcionen publicats, no només en local.
  • git status no mostra cap canvi pendent de pujar.

Rutes relatives i noms en minúscula

Enllaça sempre amb rutes relatives (contacte.html, css/estils.css), mai absolutes (/contacte.html): en local i a GitHub Pages la pàgina no viu a la mateixa arrel.

Fes servir noms de fitxer i de carpeta sempre en minúscula. El sistema de fitxers en local sol ignorar majúscules i minúscules, però els servidors de GitHub Pages no: un enllaç a Images/foto.jpg quan la carpeta es diu images falla només un cop publicat.

Si alguna cosa no va

La pàgina publicada dona un error 404

Causa Encara no has activat GitHub Pages, o el fitxer principal no es diu index.html.

Solució Revisa Settings → Pages i el nom del fitxer a l'arrel del repositori.

No surt una imatge a GitHub Pages però sí en local

Causa El nom de la carpeta o del fitxer no coincideix exactament en majúscules i minúscules amb l'enllaç de l'HTML.

Solució Fes-los coincidir: per exemple, images i no Images.

git push demana usuari i contrasenya, o el rebutja

Causa El repositori s'ha clonat per HTTPS en lloc de per SSH, o la clau SSH no s'ha afegit a GitHub.

Solució Comprova l'adreça remota amb git remote -v: ha de començar per git@github.com:. Si no, torna a clonar per SSH.
