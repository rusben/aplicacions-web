Guia: servidor de correu intern

Postfix i Dovecot a l'escriptori de laboratori: bústies Maildir, comptes i proves des del terminal.

Què hi ha en aquesta guia

Documentació oficial: Postfix · Dovecot

  • Punt de partida: un escriptori d'IsardVDI amb Ubuntu a punt (G1.1).
  • Resultat: un servidor de correu només intern al domini correu.internal, amb bústies Maildir i accés per IMAP.
  • Sobre aquest servidor s'hi connecta el correu web de G5.2.
Correu intern, no a Internet Aquest servidor no ha d'enviar correu cap a fora ni rebre'n. Un servidor de correu obert a Internet necessita DNS, registres de reputació i protecció contra abusos, i la major part de xarxes bloquegen el port de sortida. Al laboratori, els missatges van d'un usuari a un altre de la mateixa màquina.

Instal·lar Postfix i Dovecot

  1. Posa el nom de la màquina i afegeix-lo a /etc/hosts:

    sudo hostnamectl set-hostname correu
echo '127.0.0.1 correu.internal correu' | sudo tee -a /etc/hosts

  2. Instal·la els paquets. A la pantalla de Postfix, tria Internet Site i escriu correu.internal com a nom del sistema:

    sudo apt update
sudo apt install -y postfix dovecot-imapd dovecot-lmtpd mailutils

  3. Comprova que els dos serveis estan actius:

    systemctl is-active postfix dovecot
active
active

Bústies en format Maildir

  1. Digues a Postfix que entregui en Maildir dins de la carpeta de cada usuari:

    sudo postconf -e 'home_mailbox = Maildir/'
sudo postconf -e 'inet_interfaces = loopback-only'
sudo postconf -e 'mydestination = correu.internal, localhost'
sudo systemctl restart postfix

  2. Deixa només IMAP actiu i reinicia:

    sudo nano /etc/dovecot/dovecot.conf
    protocols = imap lmtp
    sudo systemctl restart dovecot

  3. Comprova els ports que escolten:

    ss -tlnp | grep -E ':25|:143'

Comptes d'usuari

  1. Crea un compte per persona. En aquest servidor, els comptes de correu són els usuaris del sistema:

    sudo adduser anna
sudo adduser pau

  2. Comprova que Dovecot els autentica:

    sudo doveadm auth test anna
passdb: anna auth succeeded

  3. Posa un àlies si vols una adreça diferent del nom d'usuari, i aplica'l:

    echo 'info: anna' | sudo tee -a /etc/aliases
sudo newaliases

  4. Per donar de baixa algú, desactiva-li el compte en lloc d'esborrar-lo, i la bústia es conserva:

    sudo usermod -L pau

Provar-ho des del terminal

  1. Envia un missatge d'un usuari a un altre:

    echo 'Primera prova' | mail -s 'Hola Pau' pau@correu.internal

  2. Mira la bústia del destinatari: cada fitxer és un missatge.

    sudo ls /home/pau/Maildir/new
1774523900.Vfd00I1M2e.correu

  3. Llegeix el registre per veure el camí que ha fet:

    sudo tail -20 /var/log/mail.log

  4. Prova l'accés IMAP tal com ho farà el correu web:

    sudo doveadm mailbox list -u pau
INBOX

Comprovació de conjunt

  • systemctl is-active postfix dovecot respon active dues vegades.
  • ss -tlnp mostra els ports 25 i 143 escoltant.
  • Un missatge enviat amb mail apareix com a fitxer dins del Maildir del destinatari.
  • sudo doveadm auth test usuari funciona amb la contrasenya del sistema.
  • mailq no té missatges encallats.

Criteris professionals

  • Al laboratori, el servidor només escolta a la mateixa màquina.
  • Un compte per persona; les adreces alternatives, amb àlies.
  • Maildir, no mbox.
  • Cada canvi, comprovat al registre abans de passar al següent.
  • Desactivar el compte en lloc d'esborrar-lo: la bústia es conserva.

Errors habituals

Els missatges van a /var/mail/usuari i no al Maildir

Causa Falta home_mailbox a Postfix.

Solució Posa-la i reinicia; els missatges antics es queden al fitxer vell.

El correu web no autentica cap usuari

Causa Dovecot no troba les bústies o l'usuari no existeix al sistema.

Solució Prova-ho amb doveadm auth test, que aïlla el problema del client.

Un missatge queda a la cua

Causa El domini del destinatari no és del servidor.

Solució Al laboratori, envia només a adreces @correu.internal; buida la cua amb sudo postsuper -d ALL.
